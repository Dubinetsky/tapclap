## Журнал тестирования

1. Запустила тестовую версию в Firefox. Игра не прошла загрузку до игрового состояния; ошибку воспроизвела повторно и зафиксировала отдельно.
2. Перешла в Chrome и вручную прошла игровой сценарий. Ближе к завершению уровня поле перестало принимать действия; состояние удалось воспроизвести повторно.
3. Стало понятно, что для проверки такого дефекта одних ручных повторов недостаточно: необходимо фиксировать состояние поля перед каждым ходом и уметь воспроизводить последовательность действий.
4. Начала с простого input probe: определила геометрию сетки и проверила, что программно отправленные действия действительно доходят до игрового canvas.
5. После первых экспериментов предложила не наращивать отдельные одноразовые сниппеты, а сделать небольшой переиспользуемый test harness и документировать способ проверки.
6. Определила движок как Cocos2d-JS и сверилась с его публичной документацией. Для дальнейшей работы выбрала public API движка как основной интерфейс; внутреннее состояние игры оставила только как возможный fallback.
7. Через scene graph нашла игровую сетку 7×7 и слой игровых элементов. По SpriteFrame удалось стабильно различать шесть типов фишек без обращения к приватной игровой логике.
8. На основе считанного состояния реализовала независимый поиск допустимых match-3 ходов и сверила результат со штатной подсказкой игры. В контрольной позиции оба способа указали один и тот же ход.
9. Добавила преобразование координат Cocos в browser coordinates и выполнение реального drag через gameCanvas. Полный цикл read, find move, input, read new state подтвердился.
10. После этого прототип был выделен в отдельную систему WARDEN: ядро для чтения состояния, выполнения повторяемых проверок и сценарных тестов.

# WARDEN

WARDEN — небольшой переиспользуемый QA-инструмент для тестовой сборки Pirate Treasures.

Он появился после ручного исследовательского тестирования, когда стало понятно, что несколько проверок приходится повторять (считывать текущее состояние поля, находить допустимые ходы match-3, ждать стабилизации поля, воспроизводить последовательности действий и сохранять диагностический снимок состояния, если игра перестаёт отвечать ожидаемым образом).

WARDEN предназначен для запуска через Snippets в Chrome DevTools. По возможности он использует публичный API Cocos2d-JS. Для текущей реализации приватное внутреннее состояние игры не требуется.

WARDEN не заменяет ручное тестирование. Он нужен для воспроизводимых повторяющихся проверок и запуска небольших сценарных сниппетов.

## Порядок загрузки

Откройте Chrome DevTools, создайте Snippets и выполните файлы в следующем порядке:

1. `warden/WARDEN-cocos-adapter-snippet.js`
2. `warden/WARDEN-input-driver-snippet.js`
3. `warden/WARDEN-hint-observer-snippet.js`
4. `warden/WARDEN-core-snippet.js`

После этого инициализируйте сессию:

```js
window.warden = await WARDEN.init({
  rows: 7,
  cols: 7,
  cellSize: 72,
  expectedTypes: 6
});
```

Основные команды:

```js
warden.read();
warden.legalMoves();
await warden.step();
await warden.run({ maxSteps: 10 });
warden.snapshot();
warden.stop();
```

## Модули

`WARDEN-core-snippet.js`

Координирует тестовую сессию. Проверяет конфигурацию, независимо от игры рассчитывает допустимые ходы match-3, ждёт стабильного состояния поля, выполняет один ход или последовательность ходов, хранит диагностическую историю и предоставляет проверки, которые используются сценарными сниппетами.

`WARDEN-cocos-adapter-snippet.js`

Считывает запущенную сцену через публичные методы Cocos2d-JS. Находит слой игрового поля, сопоставляет Cocos Nodes с логическими строками и столбцами, различает типы фишек по прямоугольникам SpriteFrame и переводит мировые координаты Cocos в клиентские координаты браузера.

`WARDEN-input-driver-snippet.js`

Содержит вспомогательные методы для ввода. Текущий драйвер отправляет события перетаскивания мышью в gameCanvas. Код ввода вынесен отдельно, чтобы позднее его можно было заменить или дополнить сенсорным вводом, не меняя считывание поля и solver.

`WARDEN-hint-observer-snippet.js`

Экспериментальный наблюдатель штатной анимации подсказки. Он считывает публично доступные положение, масштаб и прозрачность Nodes игрового поля, пытается определить две наиболее явно анимируемые соседние клетки и сравнивает эту пару с независимо рассчитанными допустимыми ходами WARDEN. Если сигнал недостаточно однозначный, возвращается AMBIGUOUS, а не сообщение о дефекте.

## Тестовые сценарии

Каталог scenarios содержит небольшие сценарные сниппеты. Они используют WARDEN и не дублируют обход сцены и код ввода.

1. `TC-01-valid-swap-snippet.js` проверяет, что рассчитанный допустимый обмен изменяет поле.
2. `TC-02-invalid-swap-snippet.js` проверяет, что соседний обмен, не создающий комбинацию, не изменяет итоговое состояние поля.
3. `TC-03-cascade-refill-snippet.js` проверяет, что после допустимого хода поле снова становится полным и стабильным.
4. `TC-04-hint-validation-snippet.js` сравнивает штатную подсказку игры с независимым расчётом допустимых ходов WARDEN.
5. `TC-05-repeated-play-snippet.js` выполняет короткую последовательность допустимых ходов и фиксирует каждый результат.
6. `TC-06-board-stability-snippet.js` проверяет, что повторное считывание уже стабильного поля возвращает одно и то же логическое состояние.
7. `TC-07-input-lock-snippet.js` сохраняет диагностический снимок, если допустимый ход отправлен в игру, но состояние поля не изменилось.
8. `TC-08-level-completion-snippet.js` продолжает игру к завершению уровня и останавливается, когда обычное игровое поле исчезает либо возникает другое условие остановки. Финальный интерфейс завершения уровня проверяется вручную.

## Текущие ограничения

WARDEN v0.1 проверен на обычном поле 7×7, которое использовалось в этой тестовой сессии.

Размеры поля и клетки настраиваются, но другие схемы уровня необходимо отдельно проверить, прежде чем доверять автоматизированным сценариям.

Текущая проверка безопасности ожидает шесть видимых типов SpriteFrame игровых фишек. Поля со специальными элементами могут потребовать другой конфигурации или дополнительного правила адаптера.

Наблюдатель подсказки остаётся экспериментальным. Статус AMBIGUOUS означает, что WARDEN не смог уверенно определить пару клеток подсказки; это не считается провалом теста игры.

Сценарий завершения уровня не пытается классифицировать все возможные окна завершения. Он останавливается, когда обычное поле исчезает, после чего финальный интерфейс проверяется вручную.

Автоматизация в настольном браузере не заменяет отдельные мобильные проверки, требуемые тестовым заданием.
